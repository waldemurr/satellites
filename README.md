# Проект: Проектирование устойчивой спутниковой группировки

## URL
http://185.157.212.168

## Описание
Веб-сервис для проектирования спутниковой группировки и оценки доступности связи в северных районах. Пользователь может загружать параметры группировки, выбирать этап развёртывания, изменять конфигурацию и проверять работу сети при отказах аппаратов.

## Фронтенд

Одостраничный интерфейс без сборки: ванильный JavaScript + **Three.js r128**
(`frontend/static/vendor/three.min.js`, локальный UMD-билд — работает полностью
offline, без CDN). Flask отдаёт `frontend/templates/index.html` на `/` и статику
из `frontend/static/` на `/static/*`; в docker-compose nginx (:3000) проксирует
`/api` на бэкенд и раздаёт те же статику и шаблон.

Возможности интерфейса (5 вкладок):

1. **Моделирование** — инженерный макет: 3D-вид по центру, панели по бокам,
   временная шкала снизу. 3D-модель Земли (сфера, гратикула, подсветка северных
   широт, звёздный фон) вращается согласно `earth_angle0_deg + OMEEGA·t`; спутники
   в Earth-fixed координатах остаются над пунктами. Спутники активные/неактивные/
   в отказе — разными цветами, ISL и связи пункт↔КА линиями, маршрут — яркой
   линией через узлы, наземные пункты — маркеры с подписями. Вращение мышью,
   зум колесом, hover/клик — инфопанель. Маршрутизация клиент→шлюз
   (hops/latency/capacity) с метриками или причиной отсутствия связи; опция
   авто-маршрута при смене t. Временная шкала: слайдер, play/pause (скорость
   0.5–4×), шаги ±, диаграмма доступности (клик/перетаскивание двигает t,
   перерывы с причинами на русском). **Тумблеры группировки**: выключение отдельных
   КА, целых плоскостей и очередей — мгновенно через параметр `exclude` бэкенда,
   без перезагрузки файла.
2. **Конфигурация** — выбор очереди запуска, дальность ISL, мин. угол места,
   RAAN/фаза плоскостей, периоды недоступности спутников и шлюзов. Кнопки
   «Применить и загрузить как новый вариант» (валидация через API) и «Сброс изменений».
3. **Эксперименты** — Монте-Карло (trials, режим poisson/fixed_k, число k,
   риск ниже целевого 90% по клиентам); эксперимент с отключением выбранных
   аппаратов или топ-N по критичности (сравнение доступности/перерывов до/после);
   рейтинг критичности аппаратов (бары).
4. **Сравнение вариантов** — сохранение отредактированных конфигураций в localStorage
   (с рассчитанными показателями), таблица различий и итоговых метрик двух вариантов,
   подсветка лучшего, текстовая рекомендация, загрузка варианта обратно в редактор.
5. **Отчёты** — полный расчёт доступности (порог 0.9, meets_target), выгрузки:
   полный отчёт JSON (мета + конфигурация + availability + таймлайны и перерывы),
   CSV по доступности, экспорт снапшота/маршрута, печать отчёта (print-CSS).

Загрузка собственного сценария — кнопка «Загрузить» или drag&drop JSON-файла;
ошибки валидации показываются списком. Скачивание текущего сценария — «Скачать».

## Функциональность

### Основные возможности:
- Выбор сценариев из предоставленных файлов данных
- Визуализация спутниковой группировки
- Интерактивная 3D-карта с отображением спутников и связей
- Расчет состояния сети в заданный момент времени
- Анализ доступности связи
- Отображение результатов расчета

### Расширенные возможности:
- Маршрутизация данных между клиентами и шлюзами
- Анализ устойчивости сети
- Вероятностный анализ рисков (Monte Carlo)
- Расчет фактической доступности связи
- Круговые и эллиптические орбиты с учётом возмущений J₂

### Используемые данные:
- `01_full_constellation.json` - Полная группировка
- `02_first_launch.json` - Первая очередь запуска
- `03_satellite_outages.json` - Недоступность десяти аппаратов
- `04_first_launch_ell.json` - Первая очередь на эллиптических орбитах (e = 0.3)
- `05_elliptical.json` - Эллиптические орбиты (перигей 744 км, апогей 3256 км; плоскость P3 с собственным эксцентриситетом)
- `06_ell_outage.json` - Эллиптическая орбита (e = 0.01) с отказом десяти аппаратов
- `06_optimal.json` - Рекомендуемая минимакс-конфигурация: 64 КА (48+16 резервных), ISL 3500 км; worst-case ≥90 % при потере до 4 КА (см. `ОПТИМИЗАЦИЯ.md`)

### Эллиптические орбиты
Расчётный модуль поддерживает круговые и эллиптические орбиты:
- `environment.orbit_type`: `circular` (по умолчанию) или `elliptical`;
- `environment.eccentricity` (0…0.6) и `environment.arg_perigee_deg` (0…360) — общие для группировки;
- спутник может переопределить оба своими полями `eccentricity` / `arg_perigee_deg`;
- ограничение: перигей не ниже 500 км (высота перигея = (6371 + altitude_km)·(1 − e) − 6371);
- для эллиптических орбит `altitude_km` — высота большой полуоси (до 5000 км);
- движение — по законам Кеплера (уравнение Кеплера методом Ньютона) с секулярными возмущениями J₂ (приплюснутость Земли): регрессия линии узлов ≈0,4°/сут и прецессия перигея ≈3–4°/сут на высоте 550 км, i = 87°; при e = 0 и J₂ = 0 расчёт совпадает с круговым двухтельным.

## API эндпоинты

### Основные эндпоинты:
- `GET /` - Главная страница
- `GET /api/health` - Проверка состояния сервиса
- `GET /api/data/files` - Список файлов данных
- `GET /api/data/<filename>` - Получение содержимого файла
- `POST /api/calculate` - Расчет состояния сети (`{file, timestamp, exclude?}`)
- `POST /api/validate` - Валидация сценария
- `GET /api/route/<filename>/<client_id>/<gateway_id>` - Расчет маршрута (`?t_s=`, `?strategy=`, `?exclude=S01,S02`)
- `GET /api/route-timeline/<filename>/<client_id>/<gateway_id>` - Таймлайн маршрута (`?strategy=`, `?step_sample=`, `?exclude=`)
- `GET /api/criticality/<filename>` - Критичность аппаратов
- `GET /api/availability/<filename>` - Расчет доступности связи
- `GET /api/monte-carlo/<filename>` - Монте-Карло анализ (`?trials=`, `?mode=poisson|fixed_k`, `?k=` число отказов)
- `POST /api/data/upload` / `GET /api/download/<filename>` - загрузка/выгрузка сценариев

Параметр `exclude` (массив id в JSON-теле или список через запятую в query)
временно отключает аппараты на весь горизонт: бэкенд клонирует сценарий в памяти
и добавляет периоды недоступности, файл на диске не изменяется.

## Поддерживаемые модули:

### 1. geometry.py (основной модуль)
- Расчет положений спутников
- Определение доступных контактов
- Геометрические расчеты

### 2. routing.py (маршрутизация)
- Построение маршрутов client -> gateway через спутниковую сеть
- Анализ причин отсутствия маршрутов
- Расширенный анализ устойчивости

### 3. availability.py (доступность)
- Расчет фактической доступности связи
- Оценка SLA-аптайма
- Расчет средней ёмкости каналов

### 4. monte_carlo.py (вероятностный анализ)
- Вероятностная оценка риска
- Моделирование случайных отказов
- Оценка устойчивости группы

# МОДЕЛЬ РАСЧЁТА РАСПОЛОЖЕНИЯ СПУТНИКОВ

**и доступности связи в LEO-группировке**

_Методология, обоснование выбора модели (защита), результаты расчётов по сценариям_

Схема данных: cosmo-A-1.0

## 1. Идея и постановка задачи

Задача — рассчитать геометрию LEO-группировки спутников связи (положения, межспутниковые линии ISL, видимость наземных станций) и на этой основе оценить фактическую доступность связи между клиентскими терминалами и шлюзом на заданном горизонте моделирования, с учётом поэтапного ввода группировки и отказов спутников/шлюзов.

Ключевое отличие от «просто визуализации орбит»: схема сценария декларирует целевой показатель target_availability, и задача считается решённой только тогда, когда модель фактически проверяет его выполнение для каждого клиента — а не останавливается на геометрическом снапшоте контактов.

### Даны

- Параметры орбиты: высота 550 км, наклонение 87°, 3 плоскости × 16 спутников (Walker-подобная схема).
- Временная сетка: горизонт до 86 400–172 800 с, шаг 120 с.
- Ограничения линий: минимальный угол места 10°, дальность ISL 2000–3000 км (варьируется по сценариям).
- Сценарии: полная группировка, первая очередь запуска (16 из 48 КА), отказ 10 аппаратов, урезанная дальность ISL, эллиптические орбиты.

### Требуется

- Положения спутников на любой момент времени.
- Граф контактов (ISL и земля-спутник) с учётом активности КА и отказов.
- Фактическая доступность связи client → gateway, сопоставленная с target_availability.

## 2. Обоснование выбора модели (защита)

### 2.1. Орбитальная динамика: аналитическая модель Кеплера + секулярные возмущения J₂, а не численное интегрирование

Движение описывается в закрытой форме: для круговых орбит аргумент широты растёт линейно, для эллиптических уравнение Кеплера `M = E − e·sin E` решается методом Ньютона (векторно, NumPy). Приплюснутость Земли учитывается секулярными скоростями первого порядка по J₂ = 1.08263·10⁻³:

- **Регрессия линии узлов:** Ω̇ = −(3/2)·J₂·n·(R/p)²·cos i
- **Прецессия линии апсид:** ω̇ = (3/4)·J₂·n·(R/p)²·(5cos²i − 1)
- **Среднее движение:** n̄ = n·(1 + (3/4)·J₂·(R/p)²·√(1−e²)·(3cos²i − 1))

где p = a(1−e²). На рабочей высоте 550 км, i = 87° это ≈0,39°/сут дрейфа узлов и ≈3,7°/сут перигея — на суточном горизонте моделирования заметно и учтено. Проверка сходимости: численный дрейф узлов за 24 ч −0,3896° против −0,3909° по теории (расхождение ~0,3%).

Обоснование выбора, а не упрощение по умолчанию:

- Задача — анализ дизайна группировки (топология, покрытие, отказоустойчивость), а не операционная навигация, где точность до метра критична.
- Аналитическая форма полностью векторизуется — критично, так как расчёт выполняется по сетке времени × парам спутников × наземным станциям × сценариям.
- Секулярная модель J₂ сохраняет закрытую форму и покрывает горизонт задания (≤48 ч); короткопериодические члены J₂ — остаток второго порядка, осознанно отброшен (см. раздел 6).

### 2.2. Эллиптические орбиты

Модель поддерживает круговые и эллиптические орбиты (параметры `orbit_type`, `eccentricity`, `arg_perigee_deg` — общие для группировки и переопределяемые на уровне отдельного аппарата). Радиус орбиты `r = a·(1 − e·cos E)`, аргумент широты `u = arg_perigee + ν`. Введено проектное ограничение: перигей не ниже 500 км — `h_perigee = (R + altitude_km)·(1 − e) − R ≥ 500`. Проверка сходимости: минимальный/максимальный радиус по орбите совпадает с a(1±e) с точностью до километра.

### 2.3. Геометрия межспутниковых линий: тест видимости через хорду, а не просто расстояние

Наивный критерий «расстояние между спутниками меньше isl_range_km» некорректен: на LEO-орбите пара спутников может быть в пределах дальности, но линия между ними проходит сквозь Землю. В реализованной модели корректно рассчитывается точка отрезка, ближайшая к центру Земли (через проекцию с ограничением параметра λ ∈ [0, 1]), и требуется, чтобы эта точка была дальше радиуса Земли. Это устраняет ложноположительные линии связи через толщу планеты.

### 2.4. Доступность связи: max-flow с ёмкостью канала, а не бинарная связность

Исходная реализация ограничивалась построением снапшота графа контактов на момент времени, но не отвечала на прикладной вопрос сценария — держит ли группировка целевую доступность. Добавленный модуль availability.py закрывает этот разрыв между спецификацией схемы (target_availability) и расчётным ядром.

Решения, заложенные в модель, и их обоснование:

- Наземные узлы не ретранслируют трафик (физическое ограничение архитектуры сети) — при построении графа пути прочие наземные точки, кроме источника (клиент) и стока (шлюз), исключаются из графа; путь всегда имеет вид client → sat → ... → sat → gateway.
- Ёмкость ребра моделируется как убывающая функция дальности (квадратичное приближение по аналогии с законом Фриза P ~ 1/d²) вместо бинарного «есть/нет» — это даёт более реалистичную метрику деградации сети вблизи предела дальности, а не резкий обрыв.
- Доступность в момент t определяется через max-flow(client, gateway) > 0 — корректно учитывает multi-hop маршруты через ISL-mesh, а не только прямую видимость.
- Несколько шлюзов объединяются через виртуальный сток стандартным приёмом multi-sink max-flow — модель расширяется на произвольное число шлюзов без изменения алгоритма.
- Итоговая availability = доля временных отсчётов горизонта, когда доступность = 1 — классическое определение SLA-аптайма, напрямую сопоставимое с target_availability из схемы сценария.

Вычислительная сложность: на каждый временной шаг решается задача max-flow на графе из ~50 узлов методом scipy.sparse.csgraph.maximum_flow — полный горизонт (720 шагов) по 3 клиентам считается за 1,5 секунды.

## 3. Математическая модель

### 3.1. Положение спутника (ECI)

- Круговая орбита: `u(t) = radians(slot_deg + phase_deg плоскости) + n·t`
- Эллиптическая орбита: `M(t) = M₀ + n̄·t`; уравнение Кеплера `M = E − e·sin E` → истинная аномалия ν; `u = arg_perigee + ω̇·t + ν`, `r = a·(1 − e·cos E)`
- `Ω(t) = radians(raan_deg) + Ω̇·t`, `i = radians(inclination_deg)`, `a = R⊕ + altitude_km`

`x = r(cosΩ·cos u − sinΩ·sin u·cos i)`
`y = r(sinΩ·cos u + cosΩ·sin u·cos i)`
`z = r·sin u·sin i`

### 3.2. Вращение Земли (переход в Earth-fixed систему)

`θ(t) = earth_angle0 + ω⊕·t`, `ω⊕ = 2π / 86164.09054 с` (звёздные сутки)

### 3.3. Тест ISL-контакта (line-of-sight через хорду)

`dist = |xyz_j − xyz_i|`; `λ = clip(−xyz_i·Δ / |Δ|², 0, 1)`; `closest = |xyz_i + λ·Δ|`
контакт: `dist < isl_range_km` И `closest > R⊕` И оба КА активны

### 3.4. Угол места и видимость наземной станции

`el = arcsin((xyz_sat − xyz_ground)·n̂_ground / |xyz_sat − xyz_ground|)`
видимость: `el ≥ min_elevation_deg` И КА активен И шлюз не в отказе

### 3.5. Ёмкость канала (модель деградации по дальности)

ISL: `cap(d) = round(max(0, 1 − (d / isl_range_km)²) · CAP)`
Земля: `cap(el) = round(min((el − el_min)/80°, 1) · CAP)`, насыщение при запасе угла места 80°

### 3.6. Доступность (SLA-метрика)

`available(t) = [max-flow(client → {gateway_1, ..., gateway_k}) > 0]`
`availability = (Σₜ available(t)) / (число отсчётов горизонта)`
SLA выполнен, если `availability ≥ target_availability`

## 4. Алгоритм расчёта (availability.py)

- Для каждого момента t на сетке [0, horizon_s) с шагом step_s:
  - Построить снапшот геометрии — positions(), snapshot() (geometry.py).
  - Для каждого клиентского терминала:
    - Построить граф max-flow: узлы — источник (клиент), активные спутники, шлюзы, виртуальный сток; рёбра — из snapshot.edges с ёмкостью по п. 3.5, прочие наземные узлы исключены.
    - Решить задачу максимального потока (scipy.sparse.csgraph.maximum_flow).
    - Зафиксировать: доступен ли клиент в момент t (flow > 0) и величину потока.
  - Агрегировать по времени: availability = доля доступных отсчётов; сравнить с target_availability.

Маршрутизация (routing.py): Dijkstra по снапшоту графа контактов со стратегиями взвешивания (число хопов / задержка распространения / узкое место по ёмкости); при отсутствии пути — классификация причины из четырёх по ТЗ (нет видимого КА у клиента, разрыв ISL-сепи, нет видимого КА у шлюза, шлюз в отказе). Вероятностный анализ (monte_carlo.py): перебор случайных наборов отказов, распределение availability по испытаниям, P(достижения цели).

### Интерпретация

- Только сценарий полной группировки (01) удовлетворяет целевой доступности для всех клиентов — подтверждает корректность проектных параметров в номинальной конфигурации.
- Первая очередь запуска (02) даёт критически низкую доступность (0.13–0.27) — количественно показывает, что промежуточный этап развёртывания не самодостаточен и требует явного плана поэтапного покрытия/резервирования на время довывода группировки.
- Отказ 10 КА (03) снижает доступность до 0.79–0.82 — заметная, но не катастрофическая деградация. Рейтинг критичности показывает узкие места (S25, S29, S21, S17 — чаще всего единственная точка отказа маршрута).
- Сокращение дальности ISL до 2000 км (04) снижает доступность сильнее (0.64–0.78), чем потеря 20 % спутников — количественно демонстрирует, что связность группировки чувствительнее к дальности лазерного канала, чем к точечным отказам узлов. Это прямой аргумент в пользу приоритизации требований к ISL-терминалам при проектировании.
- Эллиптическая конфигурация (05, апогей 3256 км над районом обслуживания) даёт 0.999–1.000 доступности при том же составе группировки — количественное обоснование резервного проекта для северных пунктов.

## 6. Ограничения модели и направления развития

- Модель ёмкости канала (квадратичная деградация по дальности) иллюстративна и не откалибрована по реальному link budget (мощность передатчика, диаграмма направленности, атмосферные потери для земных линий) — для предпусковой валидации требует замены на измеренную/расчётную характеристику аппаратуры.
- Возмущения учтены секулярно, первый порядок по J₂; короткопериодические члены J₂ и атмосферное торможение (на 550 км — существенно на горизонтах недели и дольше) не учтены — приемлемо для горизонта ≤48 ч, требует расширения для операционного использования.
- Секулярные скорости Ω̇, ω̇ считаются по средним элементам орбиты (i, a постоянны); долгопериодические вариации эксцентриситета (например, под действием J₃ для критических наклонений) не моделируются.
- Единственный шлюз в текущих сценариях — модель поддерживает multi-gateway (виртуальный сток) и отказ шлюза (gateway_outages), количественная оценка чувствительности к отказу шлюза доступна через тумблеры интерфейса.
- При кратном росте числа спутников (сотни–тысячи) потребуется замена полного перебора пар (O(N²)) на пространственный индекс (k-d дерево / grid) — направление обосновано отдельно и не входит в объём текущей реализации (48 КА: полный перебор ~мгновенен).
